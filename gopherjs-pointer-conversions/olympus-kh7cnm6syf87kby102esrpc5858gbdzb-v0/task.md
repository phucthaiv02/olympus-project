Let's fix GopherJS so that when converting a pointer to another pointer type, the result behaves the same as in Go. This applies to explicit conversions such as `P(p)` or `(*MyInt)(p)`, to implicit conversions wherever a `*T` value is used as a named pointer type it is assignable to, such as `type P *T`, or conversely, to conversions via `unsafe.Pointer` between pointer types that have the same element type or that differ only in the names of the types that compose them, such as `*[2]int64` and `*[2]MyInt64`, or structs whose field types differ in that way, and to similar operations via reflect such as `Value.Convert`, `NewAt` and `Set`.

The pointer after conversion has the destination type and is nil if and only if the source pointer is nil, where a zero `unsafe.Pointer` is also counted as nil. Otherwise, it points to the exact variable to which the source pointer points, whatever that variable is, and pointers to the same variable must be equal after being converted to the same type, including `unsafe.Pointer` and the addresses returned by reflect.

The value read through a pointer converted through `unsafe.Pointer` has the target type, including array elements and struct fields, while the value written through it retains the type of the original variable.
