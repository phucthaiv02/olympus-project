Let's fix GopherJS so that when converting a pointer to another pointer type, the result behaves the same as in Go. This applies to explicit conversions such as `P(p)` or `(*MyInt)(p)`, even when `p` is `*js.Object` and `P` is `type P *js.Object`, to implicit conversions wherever a `*T` value is used as a pointer type whose name it assigns, such as `type P *T`, or conversely, to conversions via `unsafe.Pointer` between pointer types that have the same element type, or differ only in name, such as `int64` and `MyInt64`, either pointers, arrays or structs created from different types in that way, like `*[2]int64` and `*[2]MyInt64`, and for similar operations via reflect like `Value.Convert`, `NewAt`, `Set`, `SetIterKey`, `SetIterValue` and the return value of constructors using `MakeFunc`.

The pointer after conversion has destination type and is nil if and only if the source pointer is nil, in which `unsafe.Pointer` equal to 0 is also counted as nil. Otherwise, it points to the exact variable to which the source pointer points, whatever that variable is, and pointers to the same variable must be equal after being converted to the same type, including `unsafe.Pointer` and the addresses returned by reflect. With `p` there is a pointer type whose name is defined from `*T`, `&*p` has type `*T` and is equal to the original pointer.

The value read through a pointer converted through `unsafe.Pointer` has the target type, including array elements and struct fields, while the value written through it retains the type of the original variable.
