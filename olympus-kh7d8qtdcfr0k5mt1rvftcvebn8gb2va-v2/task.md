Jedi chooses the wrong overload when the parameter is annotated with `type[...]`. With `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, when typing `get_obj(Foo).` Jedi suggests methods of both `FooBuilder` and `BarBuilder`, while only `FooBuilder` should be suggested. A parameter `type[X]` accepts class `X` and its subclasses, not instances. Annotation `type`, `Type` or `type[Any]` accepts all classes. With `type[T]` where `T` is TypeVar, the class must satisfy the bounds or one of the constraints of `T`; If `T` has no bounds and no constraints, then all classes are accepted. The `Optional[X]` parameter takes `None` and any value that `X` takes. With annotation containers like `list[X]` or `dict[K, V]`, every element of the argument must be accepted by the corresponding annotation, including elements unpacked with `*` or `**` right in the literal like `[C, *a]` or `{"k": C, **d}`; With dict, both key and value must be accepted. A value of unknown length, such as a value of type `tuple[X, ...]`, does not match a fixed-length tuple annotation such as `tuple[X]`.

Jedi should choose overload as a type checker: the first overload where every invocation argument (either by position or by name) matches the annotation will be used, and only if no overload matches will combine the results of all overloads. If a positional or name argument can have multiple types (e.g. Union), the annotation must accept all of those types. When parameters receive arguments via `*args` or `**kwargs`, annotations describing each argument are aggregated; Arguments unpacked at the call from a literal tuple, list, or dict, or from a variable containing that literal, are also counted, including elements unpacked with `*` inside the literal such as `f(*[A, *b])`. If `*args` or `**kwargs` receives no arguments, the overload still matches.
