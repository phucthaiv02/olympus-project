When a function has multiple overloads and parameters annotated with `type[...]` or `Callable`, Jedi is currently suggesting the wrong method. With the two overloads `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, when typing `get_obj(Foo).` Jedi hints at methods of both `FooBuilder` and `BarBuilder`, while it should only hint at `FooBuilder`.

Jedi should choose the overload as a type checker: the first overload that receives the call's arguments, whether they are passed by position or by name, will be used. Only if no overloads match will the combined result of all overloads be returned.

A `type[X]` (or `Type[X]`) parameter takes the class `X` and its subclasses, but not the instance. In contrast, the annotate parameter `X` does not accept the class `X` itself. `type` or `Type` has no parameters, and `type[Any]`, takes any class. Union can be inside or outside `type[...]`. With `type[T]` where `T` is TypeVar, the class must satisfy the bounds or one of the constraints of `T`; if `T` does not have both then all classes are accepted. The argument can be a direct class name, or an annotated variable or parameter `type[...]`.

The `Callable` parameter accepts anything callable (functions, lambdas, builtin functions, classes, bound methods, and class instances that have `__call__`; as in Python, `__call__` assigned exclusively to instances does not count), and rejects the normal value. Only the return type of `Callable[...]` is checked, not the parameter list: any value the callable can return must match that type. Calling a class returns an instance of that class. If the Jedi cannot deduce the result of the callable, it is considered a match.
