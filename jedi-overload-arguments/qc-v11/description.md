When a function has multiple overloads, Jedi combines the results of all overloads instead of choosing the overload that matches the call. For example, with two overloads `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, when typing `get_obj(Foo).`, the suggestion list includes methods of `BarBuilder`. Jedi should have just suggested `FooBuilder`'s methods.

I think Jedi should take the first overload that receives all the arguments of the call, whether the arguments are passed by position or by name, and compare the type according to normal typing rules. If no overload matches, then combine the results. There are a few cases I want to note, with `A` and `C` being two unrelated classes. With `f(A if c else C)`, the argument can be `C`, so overloads with `x: type[A]` parameters do not match. With `xs` having type `list[type[C]]`, `f(*xs)` can pass any number of arguments, even no arguments, so Jedi does not choose an overload with exactly one `x: type[C]` parameter. With `T = TypeVar("T", "A", int)`, `f(A, int)` does not match `x: type[T], y: type[T]`, because `T` only accepts one constraint in the entire call.

When the argument is a tuple, list, dict, or comprehension written directly in the code, Jedi should consider the actual content, both key and value, that Python creates at runtime, even if that literal is in a variable, unpacked with `*` or `**`, or nested like `f(*[A, *b])`. Some examples I have tried: `{1: A, True: C}` only has the value `C` because the two keys are equal. In `{"k": C, **d}`, if `d` can be `{"k": A}` or `{}` then `"k"` can be `A` or `C`. As for `xs = [A] if c else []`, in `f(*xs, C)`, `C` can be the first or second argument.
