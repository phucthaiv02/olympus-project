Jedi chooses the wrong overload when the parameter is annotated with `type[...]`. With `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, when typing `get_obj(Foo).` Jedi suggests methods of both `FooBuilder` and `BarBuilder`, while only `FooBuilder` should be suggested. A `type[X]` parameter accepts class `X` and its subclasses, not instances. Annotation `type`, `Type` or `type[Any]` accepts all classes. With `type[T]` where `T` is TypeVar, the class must satisfy the bounds or one of the constraints of `T`; If `T` has no bounds and no constraints, then all classes are accepted. The `Optional[X]` parameter takes `None` and any value that `X` takes. With annotation containers like `list[X]` or `dict[K, V]`, every element of the argument must be accepted by the corresponding annotation; With dict, both key and value must be accepted.

Jedi should choose overload as a type checker: the first overload where every invocation argument (either by position or by name) matches the annotation will be used, and only if no overload matches will combine the results of all overloads. If an argument passed by position or by name can have multiple types (e.g. Union), the annotation must accept all of those types. When parameters receive arguments via `*args` or `**kwargs`, annotations describing each argument are aggregated; Arguments unpacked at the call from a tuple, list or dict literal, or from a variable holding one, are also counted, as are dicts created by `dict(...)` from keyword arguments, a mapping, a list of key-value pairs, or a combination of these. These rules also apply when an overloaded function is called via `functools.partial`. If `*args` or `**kwargs` receives no arguments, the overload still matches.
