Modify Jedi so that it selects the overload according to the call's arguments like a type checker, especially when the parameter has the `type[...]` annotation. For example, with `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, when typing `get_obj(Foo).`, Jedi should only suggest methods of `FooBuilder`.

Jedi should use the first overload that accepts all arguments, whether they are passed positionally, by name, or go into `*args` and `**kwargs`. If no overload accepts those arguments, then Jedi combines the results of all overloads. Annotations follow normal typing rules. When an argument can take on multiple values, such as a Union, a conditional expression, or a value unpacked by `*` without knowing the number of elements in advance, an overload should be chosen only if it accepts all possibilities.

With an argument that is a tuple, list or dict written directly, or a variable containing it, even when unpacked with `*` or `**` or nested inside like `f(*[A, *b])`, consider the actual content that Python creates when running. For example, `{1: A, True: C}` only has the value `C`, because when two keys are equal, the value written later replaces the value written before. In `{"k": C, **d}`, if `d` can be `{"k": A}` or `{}`, then the value of `"k"` can be `A` or `C`. Comprehension on empty literals like `[C for _ in []]` has no elements. With `xs = [A] if c else []`, when calling `f(*xs, C)`, `C` can be the first or second argument.
