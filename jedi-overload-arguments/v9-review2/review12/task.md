Jedi chooses the wrong overload when the parameter has the annotation `type[...]`. With `get_obj(input: type[Foo]) -> FooBuilder` and `get_obj(input: type[Bar]) -> BarBuilder`, typing `get_obj(Foo).` Jedi suggests methods of both `FooBuilder` and `BarBuilder`, while only `FooBuilder` should be suggested.

Jedi should choose overload as a type checker: use the first overload whose annotations accept all arguments of the call (by position or by name), and only if no overload matches, combine the results of all overloads. Annotations are checked according to normal typing rules, including `type[X]`, TypeVar with bounds or constraints, `Optional`, and containers such as `list[X]`, `dict[K, V]` or `tuple[...]`, in which every element, key and value must be accepted. The `*args` and `**kwargs` parameters check each argument they receive.

If an argument can have multiple values, for example a Union or a conditional expression, then the annotation must accept all possibilities. An argument that is a literal tuple, list or dict, or a variable containing that literal, even if unpacked with `*` or `**` at the call, is considered according to the content that Python creates from the literal: including the unpacked part inside such as `f(*[A, *b])` or `{"k": C, **d}`, a later key replaces an equal earlier key (like `1` and `True`), an entry that may be absent replaces only when it is present, and a comprehension over an empty literal has no elements. For example with `xs = [A] if c else []`, in `f(*xs, C)` the `C` can be the first or second argument.
