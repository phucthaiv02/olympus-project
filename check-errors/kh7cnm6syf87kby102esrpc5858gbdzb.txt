  Description:
    Fix conversions between pointer types so that the result behaves like a pointer of the destination type, the way it does in Go. This covers explicit conversions such as `P(p)` or `(*MyInt)(p)`, and the implicit conversions that happen when a `*T` value is used where an assignable named pointer type such as `type P *T` is expected, or the other way around: function and variadic arguments, multiple results passed straight to another call, return values, struct, array, slice and map literal elements and keys, map assignments, `append`, channel sends (including in `select`), variable declarations and assignments.
    
    Several of these go wrong today. A pointer to a basic type that is passed as an argument or stored in a composite literal keeps reporting its original type to `%T`, reflection, type assertions and type switches. Converting a nil pointer to an array into another pointer type gives a value that is not equal to nil. An explicit conversion of a pointer to a basic type creates a new pointer that is not equal to the original after converting it back, nor to a second conversion of the same pointer, so it can't be relied on as a map key either.
    
    After the fix, a converted pointer has the destination type, is nil exactly when the source is nil, and refers to the same variable, so writes through either pointer are visible through the other. Converting a pointer to another type and back gives a pointer equal to the original, and converting the same pointer to the same type twice gives equal pointers, also when they are used as map keys or compared inside interfaces. This applies to pointers to basic types (including element types that differ only by name, like `*int` and `*MyInt` or `*int64` and `*MyInt64`), pointers to pointers and pointers to arrays, including pointers to slice elements and struct fields. Conversions between pointers to structs already work this way and must keep working.
    
    `unsafe.Pointer` follows the same rule for nil. Converting the zero `unsafe.Pointer` to any pointer type, including a pointer to a struct, gives that type's nil pointer, and converting a nil pointer of any type to `unsafe.Pointer` gives a value equal to nil. A non-nil pointer that goes through `unsafe.Pointer` and back to its own type keeps its identity.
